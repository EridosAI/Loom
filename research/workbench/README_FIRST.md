# Loom Research Workbench — start here

This folder is the portable starting kit for Jason's live research-authoring workspace. Its map and working notes are created by the local Work session after it verifies source custody. It is not a third mechanism proposal and it does not replace the accepted repository or the wider Atlas.

## Jason's setup

1. Extract the starter ZIP somewhere convenient. Move the contained **Loom Research Workbench** folder into your existing Obsidian vault, as an ordinary subfolder. Do not extract over the actual Loom code repository or an existing research folder. Do not place it under a generated Atlas `views/` directory.
2. Open a new **desktop-local Work** session pointed at this folder. Grant this folder, not the entire vault. Select the intended available model explicitly rather than relying on a label such as Latest.
3. Paste `START_WORK_SESSION.txt` into that session. It asks the session to read `AGENTS.md` and perform `SETUP_WORK_SESSION.md`. It authorizes documentation setup only.
4. After setup, open `00_RESEARCH_MAP.md` in Obsidian. It should link to both candidates, their review, open questions and preserved sources. Keep the downloaded starter ZIP and copy the setup recovery ZIP into your normal private backup location.

No need to copy the existing eleven-file export or the earlier candidate packages again: the relevant source material is already included and catalogued. `SETUP_PROVENANCE.md` identifies the one stale uploaded header recovered to exact pinned bytes, and the originals still missing.

## Everyday use

- Put new files or pasted notes in a uniquely named batch under `INBOX/`.
- Give the integrating Work session `IMPORT_NEW_MATERIAL.txt` with the batch name.
- Begin a new design session with `START_LATER_DESIGN_SESSION.txt`.
- Give simultaneous reviewers `START_CONTRIBUTOR_SESSION.txt` so they create their own notes instead of overwriting the map.
- At the end of a design session, request a durable session record and explicitly scoped integration. Do not rely on chat history alone.

The complete primary-chat export can arrive later. Preserve the raw account export separately, then provide the relevant conversation and associated files through controlled intake. Do not paste a whole account export full of unrelated private material into every model session.

## What not to do

Do not delete your earlier files or project uploads merely because this kit exists. Do not rename every old document Current State. Do not merge P and R without creating a distinct proposal. Do not push private sources to GitHub. Do not ask the setup session to implement a mechanism as part of organizing its notes.

The toolkit needs no plugin, custom app, database, automatic scheduler or new Obsidian vault. The initial session should leave the research easier to continue, not create another administration programme.
